Join a network. See which LLM APIs are there. 接入一个网络，
就能看到这里有哪些 LLM API。

Model servers on the local network announce themselves. Your AI app lists what is available here, like a Wi-Fi list or the printers in a print dialog, and you choose which one to use. Move to another network and the list updates. No IP addresses to type.

局域网里的模型服务会主动公告自己。你的 AI 应用把当前网络里可用的服务列出来，就像 Wi-Fi 列表，或打印对话框里的打印机列表，由你选择用哪一个。换到另一个网络，列表随之更新，不用再手动填写 IP 地址。

    The problem现状

    Using a local model usually starts with a pasted address.用一个本地模型，往往从复制粘贴地址开始。

    Team chat团队群聊

    The model server is up: http://192.168.31.47:8000/v1, model qwen2.5-72b. I'll send you the key.

    模型服务起好了：http://192.168.31.47:8000/v1，模型 qwen2.5-72b，key 私聊发你。

    config.yaml

    base_url: http://192.168.31.47:8000/v1
model:    qwen2.5-72b
api_key:  sk-••••••••••••

    Next day, on another network第二天，换了一个网络

    connect ETIMEDOUT 192.168.31.47:8000

    • Someone has to send the address, port, path and model name by hand.地址、端口、路径和模型名，都要有人手动发给你。
    • Every app on every device is set up separately.每台设备上的每个应用，都要单独配置一遍。
    • When the server's address changes, every copy of the setting breaks.服务器地址一变，所有配置都要跟着改。
    • When you move to another network, your apps still point at a server you can no longer reach.换了网络，应用仍然指向一台已经连不上的服务器。
    • It is hard to see what is available right now: a model that was just deployed, or one that went offline.很难知道此刻有哪些服务可用：刚上线的模型，或已经下线的服务。

    “When an application joins a different network or a service address changes, these settings may need to be updated even when a suitable local service is already available.”

    “当应用接入另一个网络，或服务地址发生变化时，即使本地已有合适的服务，这些设置也可能需要更新。”

    A familiar pattern熟悉的用法

    Printers and Wi-Fi already work this way.打印机和 Wi-Fi 早就是这样用的。

    You don't type a printer's IP address. You open the print dialog and pick one of the printers on this network. You don't set up a Wi-Fi network in advance. You look at the list and join one. LLM APIs can work the same way.

    打印时你不用输入打印机的 IP，而是在打印对话框里，从当前网络的打印机中选一台。连 Wi-Fi 也不用提前配置，看一眼列表就能加入。LLM API 也可以这样用。

    Wi-Fi

    See nearby networks, then join one.先看附近的网络，再选择加入。

    Printers打印机

    See the printers on this network, then print.先看当前网络的打印机，再打印。

    LLM API

    See the LLM APIs on this network, then check one and connect.先看当前网络的 LLM API，再检查并接入。

    Network printers are commonly found with mDNS and DNS-SD. This project uses the same standard protocols and adds one service type for LLM APIs: _llm-api._tcp.

    网络打印机通常就是通过 mDNS 和 DNS-SD 被发现的。本项目使用同样的标准协议，只为 LLM API 增加一个服务类型：_llm-api._tcp。

    Why it works, and why now为什么可行，为什么是现在

    AI apps already run on an API. The server behind it can change.AI 应用本来就运行在 API 之上，背后的服务器可以更换。

    A coding agent, a chat app or an IDE assistant is a front end, often called a harness. It does its work by sending requests to an LLM API server, and the model runs behind that API. Point the harness at a different server and the same app runs on a different model.

    编程 agent、聊天应用、IDE 助手，本质上都是一个前端 harness。它通过向 LLM API server 发送请求来工作，模型运行在 API 后面。把 harness 指向另一个 server，同一个应用就换成了另一个模型。

    So switching models is already possible. What is missing is a simple way for the app to find the servers that are on the network it has just joined.

    所以换用模型本身已经可行。缺的是一个简单的方法，让应用找到它刚接入的网络里有哪些 server。

    Local models are practical本地模型已经实用

    Open-weight models such as DeepSeek, Qwen and GLM run on a single workstation. Teams can keep prompts and data on their own machines.DeepSeek、Qwen、GLM 等开放权重模型，一台工作站就能运行。团队可以把提示词和数据留在自己的机器上。

    One server, many clients一台服务器，很多客户端

    One GPU machine often serves a whole team. Every laptop, agent and IDE needs its address.一台 GPU 机器常常服务整个团队，每台笔记本、每个 agent 和 IDE 都需要它的地址。

    People and services move人和服务都在变动

    Laptops move between networks all day. Services are redeployed, and addresses change.笔记本每天在不同网络之间切换，服务会重新部署，地址也会变化。

    No shared way to ask缺少统一的发现方式

    Each app has its own settings page. Scanning ports is guesswork and cannot tell what an API is or whether it needs a key.每个应用各有一套设置。扫描端口只能靠猜，也看不出是什么 API、需不需要 key。

    Scenarios场景

    Useful wherever a local network has LLM services on it.只要局域网里有 LLM 服务，就能用上。

    Moving between networks在不同网络之间切换

    Office, home, a lab, a client site, another building. Each network has its own services. When your laptop joins a network, the list shows that network's services. When it leaves, they disappear from the list. Office to home is one example; any move from one local network to another works the same way.

    公司、家、实验室、客户现场、另一栋楼，每个网络都有自己的服务。笔记本接入哪个网络，列表就显示哪个网络的服务；离开后，这些服务从列表中消失。从公司到家只是一个例子，从任意一个局域网切换到另一个局域网都是一样的。

    Saved keys stay where they are. Nothing connects until you choose a service.

    已保存的 key 不受影响。你不选择，就不会接入任何服务。

    A shared workstation in a team团队共享工作站

    One workstation serves a 32B model and a vision model. New team members open their app and pick them from the list. Nobody maintains a page of IP addresses.一台工作站提供 32B 模型和视觉模型。新同事打开应用，从列表里选择即可，不需要有人维护一份 IP 地址文档。

    A home lab家庭实验室

    A desktop with a GPU serves a model at home. Every laptop in the house finds it without setup.家里一台带 GPU 的台式机提供模型服务，家里的每台笔记本无需设置就能找到它。

    Classrooms, labs and hackathons课堂、实验室和黑客松

    Organizers run a few model servers on the venue network. Participants choose from a list instead of copying addresses from a slide.组织者在现场网络里部署几台模型服务，参与者从列表中选择，不用从幻灯片上抄地址。

    Sites without internet access没有外网的现场

    Factories, field sites and secure labs. Discovery happens entirely on the local network and needs no cloud service.工厂、野外站点、涉密实验室。发现过程完全在局域网内完成，不依赖任何云服务。

    Benefits好处

    Less setup for everyone involved.每个参与者都能少做配置。

    For people who use models对使用模型的人

    • No addresses to type or keep up to date.不用输入地址，也不用维护地址。
    • See what is available on the network you are on now.随时看到当前网络里有哪些服务。
    • Change networks without reconfiguring your apps.换网络不用重新配置应用。
    • Each service shows whether it needs a key and whether one is saved.每个服务都会显示是否需要 key、key 是否已保存。

    For people who run models对部署模型的人

    • Announce a service once. Every client on the network sees it.公告一次，网络里的所有客户端都能看到。
    • Swap the model behind an endpoint without telling everyone.更换某个接入点背后的模型，不用逐个通知。
    • Publish several APIs from one machine, each with its own key policy.一台机器可以发布多个 API，各自设定 key 要求。
    • Withdraw a service and it leaves every client's list.撤下服务后，它会从所有客户端的列表中消失。

    For people who build apps对开发应用的人

    • A small library returns checked, ready-to-use endpoints.一个小型库直接给出校验过的接入地址。
    • Standard mDNS/DNS-SD. No central server, no cloud account.基于标准 mDNS/DNS-SD，不需要中心服务器或云账号。
    • Works offline. Discovery traffic stays on the local network.离线可用，发现报文不出局域网。
    • Servers and clients that follow the same profile can find each other.遵循同一规范的服务端和客户端可以互相发现。

    How it works工作原理

    Announce, discover, then connect when you choose.公告、发现，由你决定何时接入。

    Two separate paths. Finding a service uses multicast on the local network and carries only hints. Using the service is a normal HTTPS connection, made straight to the API after you choose it.

    这里有两条独立的路径。发现服务走局域网组播，只传递线索；使用服务是普通的 HTTPS 连接，在你选择之后直接连到 API。

    What one announcement contains一条公告包含什么

    Four standard DNS-SD records. Together they give the client a complete endpoint URL, the API type and whether a key is needed. No keys, prompts or model lists travel on the network.四条标准的 DNS-SD 记录。它们合起来给出完整的接入 URL、API 类型，以及是否需要 key。网络上不传 key、提示词或模型列表。

    Safety安全

    Discovery shows you options. You decide what to trust.发现只提供选项，信任由你决定。

    No secrets on the network网络上不传密钥

    An announcement says whether a key is required. It never carries a key.公告只说明是否需要 key，从不携带 key。

    Nothing connects on its own不会自动接入

    Finding a service, or joining a new network, never connects it or changes the model you use.发现一个服务或接入新网络，都不会自动接入，也不会更换你正在用的模型。

    Connections are checked连接经过校验

    Before a key is sent, the client checks the certificate, host name and allowed addresses against its own trust settings.发送 key 之前，客户端会按自己的信任设置检查证书、主机名和允许的地址。

    A key belongs to one servicekey 只属于一个服务

    A service with the same name on another network does not get your key.另一个网络里同名的服务，拿不到你的 key。

    In this implementation, the trust settings are a file that the service operator gives to users, listing each service's address and certificate. A moved or new service needs an updated entry before it can be connected. Making trust easier to set up is an open question that the draft leaves for a later revision.

    在本实现中，信任设置是服务运营者提供给用户的一个文件，列出每个服务的地址和证书。服务换了位置或新增服务时，需要先更新对应条目才能接入。如何让信任设置更简单，是草案留给后续版本解决的问题。

    Open source开源组件

    Four parts. Use all of them or only the one you need.四个组件，可以全部使用，也可以只用需要的那个。

    If you run a model server如果你部署模型服务

    llm-api-advertiser

    Announces an existing LLM API on the local network. Command-line tool or Node.js library.在局域网中公告已有的 LLM API。可作为命令行工具，也可作为 Node.js 库使用。

    If you build a client如果你开发客户端

    llm-discovery-core

    Finds services, checks their records and follows network changes. A Node.js library with no UI.发现服务、校验记录、跟随网络变化。不带界面的 Node.js 库。

    If you use DeepSeek Harness如果你使用 DeepSeek Harness

    dsh-lan-discovery

    A plugin that lists LAN services in Harness and connects the one you choose to a normal conversation.在 Harness 中列出局域网服务，并把你选择的服务接入正常对话的插件。

    If you want to try it如果你想先体验

    llm-service-discovery-demo

    Two simulated nodes with three APIs on your own network. No GPU, model weights or cloud key needed.在你自己的网络中运行两个模拟节点、三个 API。不需要 GPU、模型权重或云端 key。

    Project status项目状态

    An experimental implementation of an IETF draft.一份 IETF 草案的实验性实现。

    The project implements Discovery of LLM API Services in Local Networks (draft-cui-dawn-local-llm-api-discovery-00). The draft is an individual submission and has no formal IETF standing. This work is for testing the idea and how well implementations work together.

    本项目实现了 IETF 互联网草案 Discovery of LLM API Services in Local Networks（draft-cui-dawn-local-llm-api-discovery-00）。该草案为个人提交，尚无 IETF 正式地位。本项目用于验证这一思路，以及不同实现之间能否互通。

    Current scope当前范围

    • IPv4 mDNS on one network interface at a time.一次在一个网络接口上使用 IPv4 mDNS。
    • Services must be on the same local network. No discovery across subnets.服务需在同一局域网内，不支持跨子网发现。
    • Following the network automatically is in the current prereleases (discovery core 0.4.0-roaming.1, Harness plugin 0.6.0-roaming.1).自动跟随网络属于当前的预发布版本（发现核心库 0.4.0-roaming.1、Harness 插件 0.6.0-roaming.1）。
    • The demo's model answers are simulated.Demo 的模型回答是模拟的。
    • No claim of full RFC or draft conformance.不声明完全符合 RFC 或草案。
