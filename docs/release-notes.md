Demo 0.7.0-roaming.1 is a prerelease for the company-to-home discovery scenario. It bundles discovery core 0.4.0-roaming.1, advertiser 0.3.1 and Harness plugin 0.6.0-roaming.1.

With `interfaceMode: auto`, the plugin follows an available LAN interface, withdraws stale candidates after a network change, and discovers services on the new network. Temporary network loss enters a waiting state. Saved credentials remain isolated by service identity; discovery does not grant access, switch an existing conversation's model, or replay interrupted requests. An older configuration containing only `interfaceAddress` keeps its pinned behavior; enable `interfaceMode: auto` explicitly to migrate.

New Demo runtimes accept `--scene company` or `--scene home`. Company presents DeepSeek-R1-Distill-Qwen-32B (32B / R1 / Q4_K_M), Qwen2.5-VL-7B-Instruct (7B / 2.5-VL / BF16), and GLM-4-9B-Chat (9B / 4 / INT4). Home presents Qwen3-8B (8B / 3 / Q8_0). These are simulated deployment metadata; no model weights or GPU inference are involved. BF16 is precision metadata. Existing runtime keys, certificates, endpoints and Mock model IDs are retained; use a new directory for a different scene.

- `llm-service-discovery-demo-0.7.0-roaming.1-native.zip` includes installed JavaScript dependencies and the plugin tgz, with no Docker image. It requires Node.js 24+ for the local OS/architecture.
- The release workflow also prepares a `windows-x64-wsl` ZIP containing the prebuilt linux/amd64 image. This candidate's local acceptance is for the native archive; building a WSL archive does not constitute a new Windows/WSL hardware or GUI acceptance.
- Verify downloads with the same release's `SHA256SUMS`; run `node scripts/verify-release-files.mjs` and `node scripts/verify-components.mjs` after extraction. GitHub's automatic Source code archives require `npm ci --ignore-scripts`.

Validation is reported in two separate layers. On Apple Silicon macOS, the unmodified core automatic resolver detected a real Wi-Fi (`en0`) to Ethernet (`en7`) change, invalidated the old candidate, discovered a newly bound local fixture through real DNS-SD UDP on isolated port 53535, and completed certificate-verified HTTPS models/responses requests. All six checks passed with no warning/error events. Both fixtures ran on the same Mac; this is not a two-remote-machine deployment or a full Desktop GUI physical-roaming test.

Separately, an isolated official Harness rc.5 Web Host exercised the plugin's actual interface with a controlled attachment signal on one physical LAN: company discovery, normal text response, image-byte transfer, a local `demo_read_marker` tool roundtrip, waiting during network loss, home rediscovery, and explicit connection followed by a new response. Multicast packets, HTTPS, credentials and Host interactions were real; inference was simulated. The illustrated document and video label this controlled UI scope explicitly.

Core 30/30 and plugin 65/65 regression tests passed. Demo source tests passed 58 checks with one PowerShell-specific check skipped on this Mac. Candidate archive checks are recorded during release preparation. Exact evidence and platform limits are in `docs/company-home-validation.md` and `docs/validation-report.md`; this prerelease does not expand claims to Linux Web UI, Intel Mac hardware, Windows ARM64 or same-address roaming on every network. Runtime certificates, credentials, private logs and user profiles are excluded.
