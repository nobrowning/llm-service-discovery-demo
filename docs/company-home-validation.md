# 公司到家：自动重新发现与演示材料

本轮候选使用 Discovery Core `0.4.0-roaming.1`、Harness 插件
`0.6.0-roaming.1`，以及 Demo 的 `--scene company|home` 场景配置。
模型名称、参数量、版本及量化/精度是模拟部署元数据，未运行模型权重。
具体配置见 [模型展示](model-presentation.md)。

## 需求与操作主线

像连接 Wi-Fi、查找附近打印机一样，用户先看到当前网络提供的服务，再检查和选择。
白天在公司使用共享的 DeepSeek、Qwen-VL、GLM 服务；回到家后，客户端重新发现
家庭的 Qwen3-8B。网络变化不会自动授权服务、转交凭据、切换会话模型或重放请求。

公司场景提供 DeepSeek-R1-Distill-Qwen-32B（32B / R1 / Q4_K_M）、
Qwen2.5-VL-7B-Instruct（7B / 2.5-VL / BF16）、GLM-4-9B-Chat（9B / 4 / INT4）；
家庭场景提供 Qwen3-8B（8B / 3 / Q8_0）。BF16 是数值精度，其他值为展示用量化配置。

## 分层验证结果（2026-11-04）

| 验证层 | 实际执行 | 结果与范围 |
| --- | --- | --- |
| 核心库回归 | 自动接口选择、DHCP/身份变化、暂态网络错误、旧 socket 数据隔离等 | 30 项通过 |
| 插件回归 | 真实 core 与控制器集成、旧连接禁用、凭据/证书隔离、显式接入和默认模型恢复 | 65 项通过 |
| Demo 回归 | 默认场景兼容、公司/家庭 profile、runtime 身份材料保留等 | 58 项通过；1 项可选 PowerShell 检查跳过 |
| 官方 Harness Web Host 界面 | 公司 3 服务 → 等待网络且无候选 → 家庭 1 服务 → 用户确认接入并完成新请求 | 单物理 LAN，受控网络附着信号；真实 UDP DNS-SD 与 HTTPS；没有顶层操作失败提示 |
| 图片与工具 | Qwen-VL 接收实际图片字节并回报摘要；GLM 发起工具调用，Host 本地执行只读 `demo_read_marker` 后回传结果 | 正常会话中的真实输入和工具往返；图像理解与模型推理仍为 Mock |
| 真实接口切换 | Wi-Fi `en0` → 有线 `en7`，采用产品默认自动解析器，不注入网络接口或解析结果 | 6 项检查通过：切换前发现和 HTTPS、真实身份变化、旧候选清除、切换后发现和 HTTPS；无 warning/error；Wi-Fi 已恢复原网络 |
| 发行包 | 插件空缓存离线安装、bundled 依赖、Host 导入与浏览器 bundle | 通过 |

物理接口验证使用同机的两个隔离 Mock API 实例，分别绑定切换前后的实际局域网地址，
各自有独立证书和信任材料。DNS-SD 使用真实组播报文，测试端口为 UDP 53535，
用于避开本机已有 Demo 的 UDP 5353。新接口上的模型列表和新请求均经过 TLS 身份校验。
这证明了真实接口变化后的核心发现与 HTTPS 链路；它不等同于两台远程公司/家庭服务器部署，
也不等同于 Desktop GUI 在两个真实 SSID 之间的完整会话验收。

原 Desktop profile、默认模型和凭据未被本轮隔离验证修改。临时关闭 Wi-Fi 后，
本地有界流程自动恢复 Wi-Fi，并通过系统界面确认重新连接到原网络。
公开材料只包含脱敏结果；实验私钥、合成凭据及本机网络地址不随材料分发。

## 启用自动重新发现

新的未固定网卡配置默认采用自动模式。已有配置含 `interfaceAddress` 时继续保持固定模式；
要迁移，在 `lan-discovery` 插件配置中显式设置 `interfaceMode: auto`。
这只改变发现接口选择，不改变 HTTPS 信任范围，也不把保存的凭据自动授权给新服务。
更详细的迁移与边界见插件仓库的 `docs/roaming.md`。
